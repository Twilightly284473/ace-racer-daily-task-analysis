# 《王牌竞速》日常任务系统反策划

## 项目简介

本项目是面向游戏数值策划岗位制作的个人作品，选取《王牌竞速》日常任务系统作为研究对象，从任务结构、活跃度效率、奖励节点和玩家完成路径四个方面进行拆解。

项目使用 Excel 建立任务配置与完成路径模型，并通过 Python 贪心算法进行交叉验证，研究以下问题：

> 在有限游戏时间内，玩家应优先完成哪些任务，才能更高效地获得日常活跃度奖励？

## 项目目标

本项目主要展示以下能力：

- 游戏系统拆解与设计意图分析
- 任务耗时、活跃度和奖励价值的数值建模
- Excel 公式与参数化配置
- Python 模型验证
- 玩家体验问题诊断与优化方案设计

## 分析方法

日常任务被划分为登录、社交、养成、比赛、排位、挑战和比赛表现等类型，并使用以下指标比较不同任务：

```text
活跃效率 = 任务活跃度 ÷ 预计完成时间
奖励效率 = 任务奖励等价值 ÷ 预计完成时间
奖励覆盖率 = 已获得节点奖励价值 ÷ 每日节点奖励总价值
```

Python 模型按照任务的活跃效率排序，在任务次数限制下，分别计算轻度、普通和全勤玩家的推荐完成路径。

## 核心结果

| 玩家路径 | 目标活跃度 | 实际活跃度 | 预计耗时 | 节点奖励覆盖率 |
|---|---:|---:|---:|---:|
| 轻度路径 | 30 | 30 | 3 分钟 | 7.5% |
| 普通路径 | 80 | 85 | 23 分钟 | 57.5% |
| 全勤路径 | 100 | 110 | 35 分钟 | 100% |

模型中的每日可获得活跃度为 150，完整奖励目标为 100，存在 50 点活跃度冗余。这意味着玩家不需要完成全部任务，可以根据时间预算和玩法偏好选择完成路径。

## 核心发现

### 1. 低成本任务适合承担启动引导

登录、签到和浏览活动等任务耗时较低、活跃效率较高，可以帮助玩家快速建立当日进度，并引导玩家进入后续玩法。

### 2. 普通路径能够覆盖主要奖励节点

模型中的普通路径约需 23 分钟，可以达到 85 点活跃度并领取 80 点奖励节点，符合普通玩家约 20～25 分钟的日常时间预算。

### 3. 活跃度冗余提供任务选择空间

每日可获得 150 点活跃度，但完整奖励只要求 100 点。玩家可以在比赛、排位、挑战和社交任务之间进行取舍，从而降低必须完成全部任务的压力。

### 4. 高约束任务的实际成本不稳定

组队、指定模式和比赛表现类任务可能受到匹配时间、队友条件及玩家技术水平影响。仅使用理论完成时间可能低估其实际成本，需要在活跃度投放和替代机制中给予补偿。

## 优化建议

### 1. 适度增加任务刷新次数

在现有任务刷新机制基础上，适度增加每日免费刷新次数，使玩家能够替换组队、指定模式或比赛表现等高约束任务。刷新后的任务应保持相近的活跃度和预计耗时，并设置次数上限，避免玩家通过反复刷新只保留最低成本任务。

### 2. 保留合理的活跃度冗余

继续保留“可获得活跃度高于完整奖励要求”的结构，让不同玩法偏好的玩家都能完成主要目标。调整任务池时，应同步检查冗余比例，避免选择空间被压缩。

### 3. 优化高耗时任务的收益匹配

对耗时较长或完成结果不稳定的任务，提高活跃度或附加奖励，使时间投入、完成难度与收益保持一致。

### 4. 强化奖励节点进度反馈

在现有领取功能基础上，突出当前活跃度、距离下一奖励节点所需活跃度，以及可以快速补足进度的任务，帮助玩家形成清晰的短期目标。

## Python 模型使用方法

运行默认模型：

```bash
python ace_racer_daily_task_model.py --output-dir model_output
```

运行内置测试：

```bash
python ace_racer_daily_task_model.py --self-test
```

生成可修改的默认配置：

```bash
python ace_racer_daily_task_model.py --write-default config.json
```

读取自定义配置并计算：

```bash
python ace_racer_daily_task_model.py --config config.json --output-dir model_output
```

模型运行后会输出 CSV 和 JSON 结果，用于与 Excel 中的完成路径进行交叉核验。

## 数据口径与限制

- 系统结构参考游戏公开信息及玩家可见内容。
- 任务耗时、活跃度和奖励等价值为作品集建模使用的示例参数。
- 示例参数不代表《王牌竞速》官方后台配置或实际商业化数据。
- 增量耗时已考虑部分任务可以在同一场比赛中同时完成。
- 贪心算法用于快速验证路径，不保证在所有自定义参数下都得到全局最优解。
- 获得可靠实机数据后，可以替换参数而不改变模型结构。

## 项目总结

本项目完成了从系统拆解、参数配置、效率分析到程序验证的完整流程。分析表明，日常任务系统同时承担玩法引导、资源投放和留存节奏控制功能；合理的活跃度冗余与刷新次数，可以在维持目标引导的同时，为不同类型玩家保留选择空间。
